# Vyntara Technologies — Employee Portal

Full-stack employee portal starter built with React + Vite, Express, Neon PostgreSQL.

## Features
- Login-first experience; employee/admin role-based dashboards.
- First login forces password change.
- Employee profile with immutable name/email/phone/employee code and editable profile photo.
- Employee project assignments, start date, deadline, status, manager/team-lead contact details.
- Employee documents: offer letter, completion certificate, recommendation letter and admin-uploaded certificates.
- Admin employee CRUD, suspend/reactivate, project/manager management, document uploads, and first-login password-change visibility.
- Employee codes generated by PostgreSQL sequence (`VYT-000001` format).

## 1. Requirements
- Node.js 20+
- Neon PostgreSQL database
- npm

## 2. Database
Create a Neon project and copy its pooled or direct connection string. Run `backend/sql/schema.sql` in the Neon SQL Editor.

## 3. Backend setup
```bash
cd backend
cp .env.example .env
# Set DATABASE_URL, JWT_SECRET, ADMIN_EMAIL, ADMIN_PASSWORD
npm install
npm run seed:admin
npm run dev
```
API runs at `http://localhost:5000`.

The seed command creates the first admin if it does not already exist. Change the temporary admin password after first login.

## 4. Frontend setup
In another terminal:
```bash
cd frontend
cp .env.example .env
npm install
npm run dev
```
Open the Vite URL (normally `http://localhost:5173`).

## 5. Production deployment
- Deploy backend to Render/Railway/Fly.io and set all backend environment variables.
- Set `CLIENT_ORIGIN` to your deployed frontend URL.
- Deploy `frontend` to Netlify/Vercel and set `VITE_API_URL` to your backend URL plus `/api`.
- Set `VITE_HOME_URL=https://vyntaralabs.tech`.
- Use persistent object storage (Cloudinary, S3, or Cloudflare R2) for uploads in production. This starter uses local `backend/uploads` storage and is suitable for local development or a persistent-volume host.
- Use HTTPS in production and rotate `JWT_SECRET` and admin credentials.

## Admin
Set `ADMIN_EMAIL` and `ADMIN_PASSWORD` in `backend/.env`, then run `npm run seed:admin`.
There is no public admin registration endpoint.

## Important security notes
- Never commit `.env`.
- Employee profile identity fields are intentionally read-only in employee endpoints.
- Admin deletion is soft deletion (`deleted_at`) so historical assignments remain auditable.
- Suspended employees cannot log in.
- Uploaded files are restricted to PDF for documents and image types for profile photos.
- For a public production deployment, move uploads to private object storage and serve downloads through authenticated endpoints.
